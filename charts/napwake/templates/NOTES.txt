Napwake is installed in namespace {{ .Release.Namespace }}.

The forecast, which learns when each workload is busy, counts hours and
weekdays in {{ .Values.timezone }}.
{{- if eq .Values.timezone "UTC" }} Set timezone to your users' zone, so workloads wake for
their mornings all year, through daylight saving. This sets it, and keeps
the other values you set:

   helm upgrade {{ .Release.Name }} oci://ghcr.io/napwake/charts/napwake --version {{ .Chart.Version }} \
     -n {{ .Release.Namespace }} --reuse-values --set timezone=Europe/London

If you install from a values file, set it there and upgrade with the file
instead: {{ $docs }}operations/upgrading/#keeping-your-settings
{{- end }}

1. Check the operator and the doorman are running:

   kubectl get pods -n {{ .Release.Namespace }}

2. See which workloads are idle and what they cost, with the kubectl plugin:

   kubectl napwake scan

3. Opt a workload in, measuring it first so nothing is paused yet:

   kubectl annotate deployment my-app -n my-namespace napwake.dev/dry-run=true
   kubectl label deployment my-app -n my-namespace napwake.dev/managed=true

   Label a namespace instead to opt in everything in it.

   Applied by Argo CD or Flux? Before enable, have it leave replicas to
   Napwake, or it scales the workload back up after every pause:
   {{ $docs }}guides/gitops/

   When you're ready, let Napwake pause it while idle:

   kubectl napwake enable my-app -n my-namespace

4. Check what it's doing:

   kubectl get managedworkloads -A
