```yaml title="napwake-values.yaml"
timezone: Europe/London
```

Put the values you set in a file, starting with your users' [time zone](/getting-started/installation/#time-zone).

```bash
helm install napwake oci://ghcr.io/napwake/charts/napwake --version 0.2.0 \
  --namespace napwake-system --create-namespace \
  -f napwake-values.yaml
```

Install with it, and upgrade with it to [keep your settings](/operations/upgrading/#keeping-your-settings).

```bash
helm show values oci://ghcr.io/napwake/charts/napwake --version 0.2.0
```

:::note[What the schema catches]
Values are checked against `values.schema.json`. A typo (`logLevel: warn`, `defaults.cpuThreshold: 0`) or an unknown value (`watchNamespace` for `watchNamespaces`), which Helm would ignore, fails the install or upgrade, not the operator. Kubernetes checks only what passes through as is, such as `resources`, `affinity`, `tolerations`, `nodeSelector`, pod annotations and labels. The schema can't list every IANA zone, so an unknown `timezone` fails at startup instead. The operator exits with `invalid --timezone` and `unknown time zone` in its log, and the rollout doesn't finish.
:::

## Names

| Value | Default | Description |
|-------|---------|-------------|
| <Ref id="nameoverride">nameOverride</Ref> | `""` | Replaces the chart name in resource names |
| <Ref id="fullnameoverride">fullnameOverride</Ref> | `""` | Replaces the full name the chart's resources are named after |

The names and labels the chart gives.

| | |
|---|---|
| Full name | The release name if it contains `napwake`, else `<release>-napwake`, cut to 40 characters so names built from it, the longest being `<fullname>-doorman-auth-delegator`, fit in 63 |
| Operator Deployment and ServiceAccount | `napwake`, for a release named `napwake` |
| The doorman's | `napwake-doorman` |
| Operator pod labels | `app.kubernetes.io/name: napwake`, `app.kubernetes.io/instance: <release>`, `control-plane: controller-manager` |
| Doorman pod labels | The same, with `control-plane: doorman` |

## CRD

| Value | Default | Description |
|-------|---------|-------------|
| <Ref id="crds-install">crds.install</Ref> | `true` | Install the ManagedWorkload CRD and upgrade it with each `helm upgrade`. Set `crds.install: false` only if you manage it, such as from `config/crd` in the repository |

:::note[Uninstall keeps the CRD]
Deleting the CRD would delete every ManagedWorkload, so it's a chart template with `helm.sh/resource-policy: keep`, and `helm uninstall` leaves it and every ManagedWorkload. For Argo CD, which ignores that, it also carries `argocd.argoproj.io/sync-options: Delete=false`, so deleting or pruning the Application leaves it too.
:::

## Defaults version

| Value | Default | Description |
|-------|---------|-------------|
| <Ref id="defaultsversion">defaultsVersion</Ref> | the chart's version, such as `0.2.0` | Which chart version Helm's defaults are from. Leave it. See [Keeping your settings](/operations/upgrading/#keeping-your-settings) |

<details>
<summary>What it's for</summary>

`helm upgrade --reuse-values` to a newer version renders with the old version's defaults, missing every value added since. Seeing `defaultsVersion` differ, the chart fills each missing value from its own defaults, `files/defaults.yaml`, a copy of `values.yaml`, which templates can't read. Values that are there stay, `false`, `0` and `""` included. With its own defaults it fills nothing, so a default removed with `null` stays removed.

</details>

## Operator

| Value | Default | Description |
|-------|---------|-------------|
| <Ref id="replicacount">replicaCount</Ref> | `1` | Operator replicas. More than one needs `leaderElection.enabled`, or the schema refuses it |
| <Ref id="leaderelection-enabled">leaderElection.enabled</Ref> | `true` | One replica reconciles, through a Lease. Without it, upgrades stop the old operator before starting the new (`strategy: Recreate`), so two never act at once |
| <Ref id="maxconcurrentreconciles">maxConcurrentReconciles</Ref> | `8` | Reconciled at once, so a slow metrics or Prometheus query doesn't hold up waking another. Sets [`--max-concurrent-reconciles`](/reference/configuration/#flag-max-concurrent-reconciles) |
| <Ref id="timezone">timezone</Ref> | `UTC` | IANA zone, such as `Europe/London`, for the [forecast's](/concepts/forecasting/#wall-clock-alignment) hours and weekdays. Use your users' zone, so forecasts follow daylight saving. Sets [`--timezone`](/reference/configuration/#flag-timezone) |
| <Ref id="pausing-enabled">pausing.enabled</Ref> | `true` | `false` stops every pause this install makes, at once, and wakes what it paused. Requests, activity and `autoResume` still wake. Sets [`--pausing=false`](/reference/configuration/#flag-pausing). See [Stop all pausing now](/guides/pause/#stop-all-pausing-now) |
| <Ref id="loglevel">logLevel</Ref> | `info` | `debug`, `info`, `error`, `panic`, or a whole number above 0 for more verbose debug levels. Operator and doorman |
| <Ref id="logencoder">logEncoder</Ref> | `json` | `json`, or `console` to read by eye. Operator and doorman |

## Resources

| Value | Default | Description |
|-------|---------|-------------|
| <Ref id="resources-requests-cpu">resources.requests.cpu</Ref> | `10m` | CPU request |
| <Ref id="resources-requests-memory">resources.requests.memory</Ref> | `128Mi` | Memory request |
| <Ref id="resources-limits-cpu">resources.limits.cpu</Ref> | `500m` | CPU limit |
| <Ref id="resources-limits-memory">resources.limits.memory</Ref> | `512Mi` | Memory limit. Raise it on clusters with many thousands of workloads |

<details>
<summary>What the operator keeps in memory</summary>

Its memory grows with the cluster.

| Objects | Held |
|---------|------|
| ManagedWorkloads, Deployments, StatefulSets, Services, Ingresses, PVCs, HPAs, Namespaces | Cached, only the watched namespaces' with `watchNamespaces` |
| Nodes | Cached without image lists |
| Pods | Cached only as spare capacity needs, if bound to a node and not finished, as node, phase and requests. About 2.6 KB each |
| The EndpointSlices it writes, the doorman Service's | Cached |
| Other EndpointSlices, ConfigMaps, KEDA ScaledObjects | Read when needed, not cached |

Go's garbage collector, in the operator and the doorman, gets a soft limit of 90% of the memory limit, leaving the rest for memory outside its heap. It works harder near the limit instead of being OOM-killed. `GOMEMLIMIT` in the pod overrides it.

</details>

## Namespaces

| Value | Default | Description |
|-------|---------|-------------|
| <Ref id="watchnamespaces">watchNamespaces</Ref> | `[]` | Namespaces Napwake works in, all if empty. Set, it gets a Role in each, not a ClusterRole, so Kubernetes refuses it anything elsewhere ([RBAC](#rbac)). Sets [`--watch-namespaces`](/reference/configuration/#flag-watch-namespaces), for the doorman too. Each install in a cluster needs its own ([more than one install](/getting-started/installation/#more-than-one-install)) |
| <Ref id="protectednamespaces">protectedNamespaces</Ref> | `[]` | Patterns, such as `prod-*`, of namespaces never managed, as if labelled `napwake.dev/protected=true`, unless labelled `napwake.dev/allow-protected=true`. `kube-*` and the operator's and doorman's namespace always are, with the same exception ([protected namespaces](/guides/opt-in/#protected-namespaces)). Sets [`--protected-namespaces`](/reference/configuration/#flag-protected-namespaces) |

```yaml title="values.yaml"
watchNamespaces: [preview-1, preview-2, staging]
protectedNamespaces: ["prod-*", production]
```

What changes with `watchNamespaces`.

- Wake on request still works. The operator always reads the doorman's EndpointSlices in the release namespace through a `<fullname>-doorman-endpoints` Role.
- A `dependsOn` into an unwatched namespace that allows the dependent's (`napwake.dev/dependents-from`) shows as `DependencyNotFound=True`, reason `DependencyNotVisible`, and never blocks it.
- An upgrade or rollback that leaves out a namespace with managed workloads, or sets `watchNamespaces` where it was empty, is refused while they're there, since they'd stay paused with no operator ([narrowing watchNamespaces](/operations/upgrading/#narrowing-watchnamespaces)).

## Opt-in defaults

For workloads opted in with the `napwake.dev/managed` label, when neither they nor their namespace set the annotation ([which setting wins](/guides/opt-in/#which-setting-wins)).

| Value | Default | Description |
|-------|---------|-------------|
| <Ref id="defaults-idleafter">defaults.idleAfter</Ref> | `1h` | Time without activity before pausing, a Go duration of at least `1m`, such as `90s` or `1h30m`. Sets [`--default-idle-after`](/reference/configuration/#flag-default-idle-after) |
| <Ref id="defaults-cputhreshold">defaults.cpuThreshold</Ref> | `10` | CPU % of requests, from 0.1 to 100 to at most two decimal places, such as `10` or `0.5`, above which it's active. Sets [`--default-cpu-threshold`](/reference/configuration/#flag-default-cpu-threshold) |
| <Ref id="defaults-dryrun">defaults.dryRun</Ref> | `false` | Measure without pausing. `true` rolls Napwake out across a cluster measuring first. Sets [`--default-dry-run`](/reference/configuration/#flag-default-dry-run) |
| <Ref id="defaults-pauseearly">defaults.pauseEarly</Ref> | `false` | Let a confident forecast of quiet hours [pause before `idleAfter`](/concepts/forecasting/#pausing-early) runs out. Sets [`--default-pause-early`](/reference/configuration/#flag-default-pause-early) |
| <Ref id="defaults-forecast">defaults.forecast</Ref> | `balanced` | How soon the forecast acts, `eager`, `balanced` or `cautious` ([Forecast setting](/concepts/forecasting/#forecast-setting)). Sets [`--default-forecast`](/reference/configuration/#flag-default-forecast) |
| <Ref id="defaults-wake">defaults.wake</Ref> | `request` | What wakes a paused workload through the doorman. `request` is any request. `ask` is only a person's click on **Wake it**, for a [public URL](/guides/preview-environments/). Sets [`--default-wake`](/reference/configuration/#flag-default-wake) |

## Doorman

| <Ref id="doorman-portsperworkload">doorman.portsPerWorkload</Ref> | `32` | Most ports one workload may hold, one per routed Service port, 1 to 10000, so one tenant can't take all 10,000 the cluster shares. | <Ref id="doorman-healthcheckuseragents">doorman.healthCheckUserAgents</Ref> | `[]` | Health checkers' and scrapers' `User-Agent` prefixes, or names after `(compatible; ` in a browser-style one, whose `GET` and `HEAD` don't wake a workload, such as `["MyCorpMonitor/"]`. | <Ref id="doorman-extraenv">doorman.extraEnv</Ref> | `[]` | Extra environment variables. The operator's `extraEnv` doesn't apply |
| <Ref id="doorman-resources-requests-cpu">doorman.resources.requests.cpu</Ref> | `10m` | CPU request |
| <Ref id="doorman-resources-requests-memory">doorman.resources.requests.memory</Ref> | `64Mi` | Memory request |

| <Ref id="doorman-negforwarder-resources-requests-cpu">doorman.negForwarder.resources.requests.cpu</Ref> | `10m` | CPU request, per pod |
| <Ref id="doorman-negforwarder-resources-requests-memory">doorman.negForwarder.resources.requests.memory</Ref> | `32Mi` | Memory request, per pod |
| <Ref id="doorman-negforwarder-resources-limits-memory">doorman.negForwarder.resources.limits.memory</Ref> | `64Mi` | Memory limit, per pod |

<details>
<summary>The doorman's memory, shutdown and rollouts</summary>

- It caches ManagedWorkloads and the EndpointSlice controller's EndpointSlices in watched namespaces, cut to what it reads, about 300 bytes a pod and 700 a Service. Held connections take up to 72Mi more under a flood.
- On Kubernetes 1.30 and later, it sleeps 5 seconds before shutting down, so kube-proxy and load balancers stop sending new connections first.
- Rollouts wait 5 seconds after a new pod is Ready (`minReadySeconds`) before stopping an old one, so the operator has moved routes to it.

</details>

## Network policy

| Value | Default | Description |
|-------|---------|-------------|
| <Ref id="networkpolicy-enabled">networkPolicy.enabled</Ref> | `false` | NetworkPolicies for the operator and the doorman |
| <Ref id="doorman-networkpolicy-ingressfrom">doorman.networkPolicy.ingressFrom</Ref> | `[]` | Peers allowed to reach paused workloads through the doorman, such as your ingress controller's namespace. Empty leaves the doorman open to every caller. Needs `networkPolicy.enabled` |
| <Ref id="doorman-networkpolicy-egress-enabled">doorman.networkPolicy.egress.enabled</Ref> | `false` | An egress policy letting the doorman connect only to `podCIDRs` and the API server. Separate from `networkPolicy.enabled`, and needs a CNI that enforces egress. The doorman needs no DNS, reaching the API server and pods by address |
| <Ref id="doorman-networkpolicy-egress-podcidrs">doorman.networkPolicy.egress.podCIDRs</Ref> | `[]` | Pod CIDRs, in every IP family. Add node CIDRs if a routed workload uses `hostNetwork`. Required when enabled |
| <Ref id="doorman-networkpolicy-egress-apiserver">doorman.networkPolicy.egress.apiServer</Ref> | `[]` | The API server's endpoint CIDRs (`kubectl get endpointslices -n default -l kubernetes.io/service-name=kubernetes`), not the `kubernetes` Service's ClusterIP. Required when enabled |
| <Ref id="doorman-networkpolicy-egress-apiserverports">doorman.networkPolicy.egress.apiServerPorts</Ref> | `[443, 6443]` | Their ports |

What the policies admit, with `networkPolicy.enabled`.

| Port | Admits |
|------|--------|
| The operator's and the doorman's metrics port | Only namespaces labelled `metrics: enabled` |
| The doorman's routing ports, TCP 20000-29999 | Every source, since every client of a paused workload's Services is sent there. With `ingressFrom` and `doorman.negForwarder.enabled`, the forwarders too, from any namespace. To narrow it, see [restricting who can reach the doorman](/concepts/wake-on-request/#restricting-who-can-reach-the-doorman) |

:::caution[On Cilium]
An `ipBlock` may not match the API server, which Cilium knows as the `kube-apiserver` entity, not by address. The egress policy can then cut the doorman off, and its pods fail readiness and log API errors. Leave `doorman.networkPolicy.egress.enabled` off, and write a CiliumNetworkPolicy allowing egress `toEntities: [kube-apiserver]` and `toCIDR` your pod CIDRs.
:::

## Guards

Without the operator, a ManagedWorkload's finalizer never runs. Its workload stays paused at 0 replicas, its Services routed to the doorman. The guards stop Helm first.

| Value | Default | Description |
|-------|---------|-------------|
| <Ref id="guard-uninstall">guard.uninstall</Ref> | `true` | Refuse `helm uninstall` while ManagedWorkloads are left, through a pre-delete hook Job, `<fullname>-uninstall-guard`. Argo CD 3.3 and later runs it as PreDelete, blocking Application deletion too. Earlier versions skip it ([uninstall](/getting-started/installation/#uninstall)) |
| <Ref id="guard-upgrade">guard.upgrade</Ref> | `true` | Refuse `helm upgrade` or `helm rollback` to a `watchNamespaces` leaving out namespaces with managed workloads, through a pre-upgrade and pre-rollback hook Job, `<fullname>-upgrade-guard`, only with `watchNamespaces` set. Argo CD runs it as PreSync, before every sync ([narrowing](/operations/upgrading/#narrowing-watchnamespaces)) |
| <Ref id="guard-nodeselector">guard.nodeSelector</Ref> | `{}` | The hooks' node selector. Empty uses the operator's |
| <Ref id="guard-tolerations">guard.tolerations</Ref> | `[]` | Empty uses the operator's |
| <Ref id="guard-affinity">guard.affinity</Ref> | `{}` | Empty uses the operator's |
| <Ref id="guard-priorityclassname">guard.priorityClassName</Ref> | `""` | Empty uses the operator's |
| <Ref id="guard-podannotations">guard.podAnnotations</Ref> | `{}` | Over `sidecar.istio.io/inject: "false"` and `linkerd.io/inject: disabled` |
| <Ref id="guard-podlabels">guard.podLabels</Ref> | `{}` | Over `sidecar.istio.io/inject: "false"`. Can't replace the chart's labels |
| <Ref id="guard-resources">guard.resources</Ref> | 10m/64Mi requests, 100m/128Mi limits | The hooks' resources |

<details>
<summary>How the guards work</summary>

Each runs the operator's image with [`--guard`](/reference/configuration/#flag-guard), waits two and a half minutes for ManagedWorkloads being deleted, lists those it would leave without an operator, and fails. Helm stops before changing anything and prints the list.

| Guard | Counts |
|-------|--------|
| Uninstall | Every ManagedWorkload in the watched namespaces (all, without `watchNamespaces`), and any elsewhere with this operator's `napwake.dev/cleanup` finalizer. None another install stamped with its namespace in `napwake.dev/operator` |
| Upgrade | Those the operator took on in namespaces the new `watchNamespaces` leaves out |

- Each runs as a ServiceAccount of its own name, with a ClusterRole that may only list ManagedWorkloads' metadata, cluster-wide even with `watchNamespaces`, since those it looks for may be outside it.
- The ServiceAccounts and RBAC are hooks too, deleted after the run. A failed Job stays an hour, for `kubectl logs`.
- The hooks use `image`, `imagePullSecrets` and `logLevel`.
- Mesh sidecars are kept out, since a running sidecar would keep the Job from finishing.
- Their pods carry `control-plane: uninstall-guard` or `control-plane: upgrade-guard`, so the operator's Service and NetworkPolicy don't select them.
- `--no-hooks` skips both.

</details>

## RBAC

What the operator's ClusterRole, `<fullname>-manager`, grants by default.

| Resource | Access | For |
|----------|--------|-----|
| ManagedWorkloads | Manage | Including creating them for labelled workloads |
| Namespaces | Read | The `napwake.dev/managed` label and settings annotations |
| Deployments, StatefulSets | Read, scale (scale subresource), patch | Patching sets and removes `napwake.dev/paused-from` while paused. It can't delete them, and changes nothing else |
| PersistentVolumeClaims | Read | Pricing a paused workload's storage |
| HorizontalPodAutoscalers, KEDA ScaledObjects | Read, and annotate ScaledObjects | Pausing a KEDA workload through KEDA |
| Pod metrics, from metrics-server | Read | |
| Pods | Read, watch | Pricing what pausing frees, sidecars included, and measuring spare node capacity for [saved](/concepts/cost-tracking/#how-saved-is-measured). Cached only if bound to a node and not finished, as node, phase and requests |
| Nodes | Read | Pricing at instance types' list prices, measuring spare capacity. Cached without image lists |
| Karpenter's NodePools, Cluster Autoscaler's `cluster-autoscaler-status` ConfigMap, Deployments in `kube-system` | List NodePools and Deployments, get the ConfigMap | Reporting the node autoscaler (`napwake_node_autoscaler`). Reads NodePools' names and consolidation settings, only the rest's metadata |
| ConfigMaps | Get, one at a time, uncached | [Learning dependencies](/concepts/dependencies/#learned-dependencies) from those a workload's environment references. Can't list or change them |
| Events | Create | User-facing status updates |
| Services | Read | |
| EndpointSlices | Manage | Routing paused workloads to the doorman |

The other roles.

| Role | Kind, and when | Grants |
|------|----------------|--------|
| `<fullname>-doorman` | ClusterRole, for the doorman's own ServiceAccount | Read ManagedWorkloads and EndpointSlices, get the pods a woken workload's endpoints name (to check each address is its pod's), patch ManagedWorkloads to wake them, create Events. With `doorman.admissionPolicy.enabled`, patches only set the two request annotations, and the one counting what it [turned away](/concepts/wake-on-request/#what-it-turns-away) |
| `<fullname>-doorman-wake-key` | Role in the release namespace, for the doorman | `get` and `update` on one Secret of the same name, which the chart creates empty. The doorman fills it with the key it signs the [Wake it button](/concepts/wake-on-request/#the-wake-it-button) with. It can't read or list any other |
| `<fullname>-leader-election` | Role in the release namespace, with leader election | Leases (`get`, `create`, `update`) and Events |
| `<fullname>-doorman-endpoints` | Role in the release namespace, with `watchNamespaces` | Read the doorman's EndpointSlices |
| `<fullname>-forwarder` | ClusterRole, or a Role per watched namespace, with `doorman.negForwarder.enabled` | `create` and `delete` Deployments for the [forwarders](/concepts/wake-on-request/#gke-container-native-load-balancing-negs). Deletes only its own, owned by a ManagedWorkload. Forwarders run as the namespace's `default` ServiceAccount, without its token or API access |
| `<fullname>-view` | Aggregated into `view`, `edit`, `admin` | Namespace viewers may `get`, `list`, `watch` its ManagedWorkloads, as `kubectl napwake status` and `scan` do. Kustomize's `managedworkload-viewer-role` is aggregated alike |
| `<fullname>-edit` | Aggregated into `edit`, `admin` | Namespace editors may `create`, `update`, `patch`, `delete` its ManagedWorkloads, as `pause`, `wake` and `enable` do. Kustomize's `managedworkload-editor-role` is aggregated alike |

What changes with `watchNamespaces`.

- The operator and the doorman get a Role and RoleBinding in each watched namespace instead.
- The operator keeps one ClusterRole, to read Namespaces and Nodes and list Karpenter's NodePools, which only a ClusterRole can grant.
- Workloads elsewhere can't be read, scaled or opted in. Dependencies on them aren't held or woken.
- With `metrics.enabled` and `metrics.secure`, both keep cluster-wide `system:auth-delegator` bindings, good only for checking scrapers' tokens.

Everything Napwake reads, writes and sends is in [Data and access](/reference/data-and-access/).

## Example production configuration

```yaml title="values-production.yaml"
replicaCount: 2

leaderElection:
  enabled: true

timezone: Europe/London

resources:
  requests:
    cpu: 100m
    memory: 256Mi
  limits:
    cpu: "1"
    memory: 1Gi

metrics:
  enabled: true
  secure: true
  readerSubjects:
    - kind: ServiceAccount
      name: prometheus-k8s
      namespace: monitoring
  serviceMonitor:
    enabled: true
    interval: 15s
  prometheusRule:
    enabled: true

protectedNamespaces: ["prod-*"]

affinity:
  podAntiAffinity:
    preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchLabels:
              app.kubernetes.io/name: napwake
              control-plane: controller-manager
          topologyKey: kubernetes.io/hostname
```

`affinity` applies to the doorman too, unless `doorman.affinity` is set. Its replicas spread across nodes by default.

```bash
helm install napwake oci://ghcr.io/napwake/charts/napwake \
  --version 0.2.0 \
  -f values-production.yaml \
  -n napwake-system --create-namespace
```
