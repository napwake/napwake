## Columns

What `kubectl get managedworkloads` shows.

| Column | Shows |
|--------|-------|
| `Phase` | The phase |
| `Freed` | What pausing freed this month |
| `Saved` | What of that it saved |
| `Would Free` | What dry-run measured it would free. Blank outside dry-run |
| `Forecast` | With `-o wide`, whether the forecast acts, or what it waits for |
| `Age` | Age |

## Spec (`ManagedWorkloadSpec`)

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| <Ref id="spec-target">target</Ref> | `WorkloadRef` | required | The workload. Can't be changed once set |
| <Ref id="spec-target-kind">target.kind</Ref> | `Deployment` or `StatefulSet` | `Deployment` | Its kind |
| <Ref id="spec-target-name">target.name</Ref> | string | required | Its name, same namespace |
| <Ref id="spec-idlepolicy">idlePolicy</Ref> | `IdlePolicySpec` | | Idle detection. Without it, never paused automatically |
| <Ref id="spec-idlepolicy-idleafter">idlePolicy.idleAfter</Ref> | duration, at least `1m` | `1h` | Time without activity before pausing |
| <Ref id="spec-idlepolicy-activity-cputhreshold">idlePolicy.activity.cpuThreshold</Ref> | int or string, 0.1-100, to two places | `10` | CPU % of requests above which it's active. A decimal is written as a string, such as `"0.5"` |
| <Ref id="spec-idlepolicy-activity-prometheus-promql">idlePolicy.activity.prometheus[].promQL</Ref> | string | required in each entry | PromQL instant query. Above zero is activity. At most 10 |
| <Ref id="spec-idlepolicy-autoresume">idlePolicy.autoResume</Ref> | bool | `false` | Wake ahead of confident forecast demand |
| <Ref id="spec-idlepolicy-pauseearly">idlePolicy.pauseEarly</Ref> | bool | `false` | Pause after 20 idle minutes, before `idleAfter`. Only if a confident forecast expects quiet until then, and the doorman would wake it. See [Pausing early](/concepts/forecasting/#pausing-early) |
| <Ref id="spec-dependson">dependsOn[]</Ref> | `DependencyRef` | | Workloads this one needs. At most 20 |
| <Ref id="spec-dependson-namespace">dependsOn[].namespace</Ref> | string | this namespace | Its namespace |
| <Ref id="spec-dependson-kind">dependsOn[].kind</Ref> | `Deployment` or `StatefulSet` | required | Its kind |
| <Ref id="spec-dependson-name">dependsOn[].name</Ref> | string | required | Its name |
| <Ref id="spec-dependson-waitforready">dependsOn[].waitForReady</Ref> | bool | `false` | Hold this one's resume until it's Ready |
| <Ref id="spec-wake">wake</Ref> | `WakeSpec` | | What wakes it through the doorman while paused |
| <Ref id="spec-wake-mode">wake.mode</Ref> | `Request` or `Ask` | `Request` | What wakes it through the doorman. `Request` is any request but a known probe's. `Ask` is only a person's click on **Wake it**, and anything else gets a `503`. See [Asking before waking](/concepts/wake-on-request/#asking-before-waking) |
| <Ref id="spec-wake-maxwait">wake.maxWait</Ref> | duration, at most `1h` | `2m` | How long a request is held while it wakes |
| <Ref id="spec-wake-page">wake.page</Ref> | bool | `true` | Answer a browser's page load with the waking-up page, instead of holding it. With `mode: Ask`, a browser always gets a page |
| <Ref id="spec-prediction">prediction</Ref> | `PredictionSpec` | `{}` | The forecast. Left out or `{}`, it takes the defaults |
| <Ref id="spec-prediction-mode">prediction.mode</Ref> | `eager`, `balanced` or `cautious` | `balanced` | How soon the forecast acts, at confidence 60, 75 or 85. See [Forecast setting](/concepts/forecasting/#forecast-setting) |
| <Ref id="spec-prediction-confidence">prediction.confidence</Ref> | int, 50-100 | the mode's | Accuracy (1 − WAPE, %) a season's forecasts must reach to drive decisions. Overrides the mode's |
| <Ref id="spec-costtracking">costTracking</Ref> | `CostTrackingSpec` | | Your own cost rates |
| <Ref id="spec-costtracking-rates">costTracking.rates</Ref> | [`CostRates`](#costrates) | node list prices, then AWS defaults | Custom rates, none negative |
| <Ref id="spec-dryrun">dryRun</Ref> | bool | `false` | Measure without pausing. Turning it on wakes a paused workload. See [Dry run](/guides/dry-run/) |

### Durations

| Duration | |
|----------|---|
| `45s`, `90m`, `1h30m` | Go durations above zero work |
| `1d`, `2w`, spaces | Days, weeks and spaces don't. Write `24h` or `168h` |
| Anything else | The API server rejects it |

### CostRates

For `costTracking.rates` and `cost.listRates`.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| <Ref id="costrates-cpuperhour">cpuPerHour</Ref> | quantity | `0.031` | USD per vCPU-hour |
| <Ref id="costrates-memoryperhour">memoryPerHour</Ref> | quantity | `0.004` | USD per GiB-hour |
| <Ref id="costrates-storagepermonth">storagePerMonth</Ref> | quantity | `0.08` | USD per GiB-month |

## Status (`ManagedWorkloadStatus`)

| Field | Type | Description |
|-------|------|-------------|
| <Ref id="status-phase">phase</Ref> | [`WorkloadPhase`](#workloadphase-values) | Current lifecycle phase |
| <Ref id="status-conditions">conditions[]</Ref> | `Condition` | Standard Kubernetes conditions. See [Conditions and events](/reference/conditions-and-events/#status-conditions) |
| <Ref id="status-lastactedat">lastActedAt</Ref> | time | Last pause or wake, by Napwake or a scale-up from zero outside it |
| <Ref id="status-lastpauserequest">lastPauseRequest</Ref> | string | Last `napwake.dev/pause-requested` value acted on, so each acts once. Outcome in the `PauseRequest` condition. See [Pause now](/guides/pause/#pause-now) |
| <Ref id="status-lastwakerequest">lastWakeRequest</Ref> | string | Last `napwake.dev/wake-requested` value acted on, so each acts once. Outcome in the `WakeRequest` condition. See [Wake now](/guides/pause/#wake-now) |
| <Ref id="status-turnedaway">turnedAway</Ref> | `TurnedAway` | With `wake.mode: Ask`, what the doorman turned away during the current pause, or the last once it's awake. `pausedAt`, when that pause began, and `requests`. Brought up to date about once a minute. See [What it turns away](/concepts/wake-on-request/#what-it-turns-away) |
| <Ref id="status-lasttransitiontime">lastTransitionTime</Ref> | time | Last phase change |
| <Ref id="status-learneddependencies">learnedDependencies</Ref> | `LearnedDependencies` | Found by Napwake, held and woken like `dependsOn`. Fields `from`, `at` and `dependencies`. Each dependency has `namespace`, `kind`, `name` and `source`. `source` is `environment` (with `via`, `address`) or `wake` (with `lastSeen`). See [Learned dependencies](/concepts/dependencies/#learned-dependencies) |
| <Ref id="status-lastscaledup">lastScaledUp</Ref> | `ScaledUp` | Last scale-up outside Napwake while paused, which wakes it. Fields `at`, `replicas`, `by` and `gitOps`. `by` is the field manager, such as `argocd-controller`. It's `unknown` through the scale subresource, which records none, as with `kubectl scale`. `gitOps` is `Argo CD`, `Flux`, `Fleet`, `kapp` or `Kluctl`, if from Git. See [GitOps tools](/guides/gitops/) |
| <Ref id="status-doorman">doorman[]</Ref> | `DoormanRoute` | Service ports routed to the doorman while paused, with `service`, `portName`, `doormanPort` and `forwarded` (behind GKE NEGs, through the [forwarder](/concepts/wake-on-request/#gke-container-native-load-balancing-negs)) |
| <Ref id="status-doormandraining">doormanDraining[]</Ref> | `DrainingPort` | Doorman ports that routed it until it woke, with `port` and `until`. No other workload gets the port before `until`, so a late client never reaches another. Kept in status, so an operator that restarts or becomes leader honours it |
| <Ref id="status-nginxingresses">nginxIngresses[]</Ref> | `NginxIngress` | The ingress-nginx Ingresses in front of the Services its last pause routed, read again while it's awake. Each has `name`, `services`, `proxyReadTimeout` (the annotation as written, unset without one) and `readTimeout`, how long ingress-nginx waits: 60s without the annotation, unset when it isn't whole seconds. See [A wake that outlasts ingress-nginx's timeout](/concepts/wake-on-request/#a-wake-that-outlasts-ingress-nginxs-timeout) |
| <Ref id="status-lastslowwake">lastSlowWake</Ref> | `SlowWake` | The last wake by a request that took longer than one of `nginxIngresses` waits, under `wake.maxWait`. `began`, when the doorman took the request, and `took`, to the first Ready replica. Kept while `IngressTimeoutShort` is `True` |

### `activity`

| Field | Type | Description |
|-------|------|-------------|
| <Ref id="status-activity-lastactivitytime">activity.lastActivityTime</Ref> | time | Latest activity, any source |
| <Ref id="status-activity-lastactivitysource">activity.lastActivitySource</Ref> | string | `created`, `woke`, `request`, `cpu`, `rollout`, `annotation`, `prometheus`, `unobserved` or `scaled-up` |
| <Ref id="status-activity-pauseat">activity.pauseAt</Ref> | time | When it pauses without more activity |
| <Ref id="status-activity-lastevaluatedtime">activity.lastEvaluatedTime</Ref> | time | Last activity check |
| <Ref id="status-activity-templatehash">activity.templateHash</Ref> | string | Pod template fingerprint, to detect deploys |
| <Ref id="status-activity-heldbydependents">activity.heldByDependents</Ref> | []string | Awake dependents keeping it from pausing (`HeldByDependents`), as `namespace/name`. At most 10, first by name |
| <Ref id="status-activity-forecastbusyfrom">activity.forecastBusyFrom</Ref> | time | Start of the hour of expected demand, while the forecast holds off the pause (`IdleVetoed`) |
| <Ref id="status-activity-forecastquietuntil">activity.forecastQuietUntil</Ref> | time | End of the quiet hours expected when the forecast brought the pause forward (`PausedEarly`). Kept until the pause, or dry-run's would-be pause, ends |

### `pause`

| Field | Type | Description |
|-------|------|-------------|
| <Ref id="status-pause">pause</Ref> | `PauseStatus` | What a pause changed, from before scaling to zero until running again |
| <Ref id="status-pause-previousreplicas">pause.previousReplicas</Ref> | int32 | Replicas before the pause, restored on resume |
| <Ref id="status-pause-startedat">pause.startedAt</Ref> | time | When the pause began, as it went `Pausing`, before anything was scaled. Or when Napwake took up a pause whose record was lost. The asleep page's **Wake it** button is good for this pause alone. See [The Wake it button](/concepts/wake-on-request/#the-wake-it-button) |
| <Ref id="status-pause-routeswrittenat">pause.routesWrittenAt</Ref> | time | When the doorman's routes for this pause were stored in status, which every doorman pod listens on. Its EndpointSlices go in 5 seconds after. Unset for a workload the doorman doesn't route |
| <Ref id="status-pause-routedat">pause.routedAt</Ref> | time | When the doorman's EndpointSlices first stood in front of its Services for this pause, beside its pods. It's scaled to zero a few seconds after. Unset for a workload the doorman doesn't route. See [What happens in a pause](/guides/pause/#what-happens-in-a-pause) |
| <Ref id="status-pause-requested">pause.requested</Ref> | bool | The pause was asked for, with `napwake.dev/pause-requested`, not decided by the idle clock or the forecast |
| <Ref id="status-pause-cpubefore">pause.cpuBefore</Ref> <Ref id="status-pause-cpujustbefore">pause.cpuJustBefore</Ref> | string | The most CPU it used, as a percentage of its requests. `cpuBefore` is through the stretch without activity that ran its clock out. `cpuJustBefore` is in its last 15 minutes, or `idleAfter` if shorter. Unset when none was measured. See [Paused while in use](/concepts/idle-detection/#paused-while-in-use) |
| <Ref id="status-pause-pausedat">pause.pausedAt</Ref> | time | When scaled to zero, unset before. `Paused` once its pods stop |
| <Ref id="status-pause-resumedat">pause.resumedAt</Ref> | time | When the current resume scaled it up. Scaled to zero after that, not by Napwake, it's left off |
| <Ref id="status-pause-firstreadyat">pause.firstReadyAt</Ref> | time | When the current resume first saw a replica Ready. The rest get 2 minutes more |
| <Ref id="status-pause-scaledobject">pause.scaledObject</Ref> | string | KEDA ScaledObject held at zero while paused. See [HPA and KEDA](/guides/autoscalers/) |
| <Ref id="status-pause-scaledobjectpausedreplicas">pause.scaledObjectPausedReplicas</Ref> | string | Its own `autoscaling.keda.sh/paused-replicas` before the pause, put back after |
| <Ref id="status-pause-resources">pause.resources</Ref> | `ResourceSnapshot` | What it ran as the pause began, the base for savings. `replicas`, per replica `cpuMillis`, `memoryBytes`, claims' `storageBytes`, and `nodePools` (`name`, `""` without a pool label, and its `pods`) |
| <Ref id="status-pause-wakeannotations">pause.wakeAnnotations</Ref> | object | Activity annotations on the ManagedWorkload (`workload`) and target (`target`) as the pause began. A change wakes it |
| <Ref id="status-pause-queryactivesincepause">pause.queryActiveSincePause</Ref> | bool | A [Prometheus activity query](/guides/prometheus-signals/#while-the-workload-is-paused) has been active at every check since a requested pause began. They don't wake it until a check finds all quiet |

### `idleWait`

| Field | Type | Description |
|-------|------|-------------|
| <Ref id="status-idlewait">idleWait</Ref> | `IdleWaitStatus` | Pauses made while it was in use, which lengthen its idle clock, and its CPU use idle. See [Paused while in use](/concepts/idle-detection/#paused-while-in-use) |
| <Ref id="status-idlewait-wrongpauses">idleWait.wrongPauses</Ref> | int32 | Pauses in a row its own use undid soon after they began. Each doubles how long the idle clock waits, up to `idleAfter` plus an hour. A pause that holds sets it back to zero |
| <Ref id="status-idlewait-lastwrongpause">idleWait.lastWrongPause</Ref> | `WrongPause` | The latest. `pausedAt`, `after` (how soon it was undone), `by` (`request`, `click`, `wakeRequest` or `annotation`), `from` (the caller's address, for a request), and `inUseCPU` |
| <Ref id="status-idlewait-idlecpu">idleWait.idleCPU</Ref> <Ref id="status-idlewait-idlecpuat">idleWait.idleCPUAt</Ref> | string, time | The most CPU it used, as a percentage of its requests, before its pauses that held, over the last week. `idleCPUAt` is when it was last measured |

| <Ref id="status-dryrun-since">dryRun.since</Ref> | time | When measuring started |

| <Ref id="status-dryrun-queryactivesincepause">dryRun.queryActiveSincePause</Ref> | bool | As [`pause.queryActiveSincePause`](#status-pause-queryactivesincepause), since the would-be pause under way was asked for. Queries don't end it until all are quiet |

### `prediction`

|-------|------|-------------|

| <Ref id="status-cost-projectedmonthlycost">cost.projectedMonthlyCost</Ref> <Ref id="status-cost-projectedmonthlyfreed">cost.projectedMonthlyFreed</Ref> <Ref id="status-cost-projectedmonthlysavings">cost.projectedMonthlySavings</Ref> | string | The month so far, carried to a full month. `pending` until a day is tracked |

| <Ref id="status-cost-pricedat">cost.pricedAt</Ref> <Ref id="status-cost-pricedtemplatehash">cost.pricedTemplateHash</Ref> | time, string | When requests and list rates were last read, and the pod template then |
