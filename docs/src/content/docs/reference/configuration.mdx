## Operator flags

### Metrics and probes

| Flag | Default | Description |
|------|---------|-------------|
| <Ref id="flag-metrics-bind-address">{'--metrics-bind-address'}</Ref> | `0` (disabled) | Metrics address, `:8443` for HTTPS or `:8080` for HTTP. The chart and the Kustomize manifests use `:8443` |
| <Ref id="flag-metrics-secure">{'--metrics-secure'}</Ref> | `true` | HTTPS, only to callers allowed to `get` `/metrics` (TokenReview, SubjectAccessReview). A scraper needs such a token, which the chart's `metrics.readerSubjects` binds ([Monitoring](/operations/monitoring/)). `false` is plain HTTP. See [TLS configuration](#tls-configuration) |
| <Ref id="flag-metrics-cert-path">{'--metrics-cert-path'}</Ref> | | Metrics TLS certificate directory. Without it, a self-signed one is generated |
| <Ref id="flag-metrics-cert-name">{'--metrics-cert-name'}</Ref> | `tls.crt` | Certificate file |
| <Ref id="flag-metrics-cert-key">{'--metrics-cert-key'}</Ref> | `tls.key` | Key file |
| <Ref id="flag-enable-http2">{'--enable-http2'}</Ref> | `false` | Allow HTTP/2 for metrics |
| <Ref id="flag-health-probe-bind-address">{'--health-probe-bind-address'}</Ref> | `:8081` | Probe address. See [Endpoints](#endpoints) |

### Operator

| Flag | Default | Description |
|------|---------|-------------|
| <Ref id="flag-leader-elect">{'--leader-elect'}</Ref> | `false` | One replica reconciles. A leader that stops releases its lease, so the next, or a rollout's new one, takes over at once. Ignored by the doorman, where every replica serves traffic. See [Leader election](#leader-election) |
| <Ref id="flag-max-concurrent-reconciles">{'--max-concurrent-reconciles'}</Ref> | `8` | ManagedWorkloads reconciled at once, so a slow metrics or Prometheus query doesn't hold up wakes, which queue ahead of periodic checks. At least 1 |
| <Ref id="flag-timezone">{'--timezone'}</Ref> | `UTC` | IANA zone, such as `Europe/London`, for forecasts' hours and weekdays, so they follow daylight saving. Zone database built in |
| <Ref id="flag-pausing">{'--pausing'}</Ref> | `true` | Pause idle workloads. `false` stops every pause this install makes, at once, and wakes those paused. Each workload is measured as in dry-run, whatever it sets. Helm value `pausing.enabled`. See [Stop all pausing now](/guides/pause/#stop-all-pausing-now) |
| <Ref id="flag-kubeconfig">{'--kubeconfig'}</Ref> | in-cluster | Kubeconfig path, outside the cluster only |

### Prometheus

| Flag | Default | Description |
|------|---------|-------------|
| <Ref id="flag-prometheus-url">{'--prometheus-url'}</Ref> | | Prometheus API base URL, `http` or `https` with a host, such as `http://prometheus.monitoring.svc:9090`. Needed for `idlePolicy.activity.prometheus`. Starts each new workload's forecast from up to four weeks of CPU history. See [Learning from history](/concepts/forecasting/#learning-from-history) |
| <Ref id="flag-prometheus-selector">{'--prometheus-selector'}</Ref> | | Matchers added to the operator's own (history) query, such as `cluster="staging"`. Written as inside PromQL's braces, with `=`, `!=`, `=~` or `!~` and a double-quoted or backquoted value, comma-separated. For a Prometheus with several clusters' series, so another cluster's same-named pods aren't read as this one's. Workloads' activity queries run as written. Needs `--prometheus-url` |

### Namespaces

| Flag | Default | Description |
|------|---------|-------------|
| <Ref id="flag-watch-namespaces">{'--watch-namespaces'}</Ref> | every namespace | Comma-separated namespaces to work in, a Role in each |
| <Ref id="flag-protected-namespaces">{'--protected-namespaces'}</Ref> | | Comma-separated patterns, such as `prod-*`, of namespaces never managed, as if labelled `napwake.dev/protected=true`, unless labelled `napwake.dev/allow-protected=true`. `kube-*`, `openshift-*`, `cattle-*`, `gke-*`, `gmp-*`, `$POD_NAMESPACE` and the doorman's namespace are always protected. See [Protected namespaces](/guides/opt-in/#protected-namespaces) |

### Opt-in defaults

For workloads opted in with the label, when neither they nor their namespace set it.

| Flag | Default | Description |
|------|---------|-------------|
| <Ref id="flag-default-idle-after">{'--default-idle-after'}</Ref> | `1h` | Idle time before pausing. At least `1m` |
| <Ref id="flag-default-cpu-threshold">{'--default-cpu-threshold'}</Ref> | `10` | CPU % of requests that counts as active. 0.1 to 100, at most two decimal places |
| <Ref id="flag-default-dry-run">{'--default-dry-run'}</Ref> | `false` | Measure without pausing, unless `napwake.dev/dry-run` is set |
| <Ref id="flag-default-pause-early">{'--default-pause-early'}</Ref> | `false` | Let a confident forecast of quiet hours pause before `idleAfter` runs out, unless `napwake.dev/pause-early` is set. See [Pausing early](/concepts/forecasting/#pausing-early) |
| <Ref id="flag-default-forecast">{'--default-forecast'}</Ref> | `balanced` | How soon the forecast acts, `eager`, `balanced` or `cautious`, unless `napwake.dev/forecast` is set |
| <Ref id="flag-default-wake">{'--default-wake'}</Ref> | `request` | What wakes a paused workload through the doorman, `request` or `ask`, unless `napwake.dev/wake` is set. See [Asking before waking](/concepts/wake-on-request/#asking-before-waking) |

### Doorman

| Flag | Default | Description |
|------|---------|-------------|
| <Ref id="flag-doorman-service">{'--doorman-service'}</Ref> | `napwake-doorman` | The doorman's Service, where paused workloads are routed. Empty turns off wake on request |
| <Ref id="flag-doorman-ports-per-workload">{'--doorman-ports-per-workload'}</Ref> | `32` | Most doorman ports per workload, one per routed Service port. Over it, it isn't routed (`WakeOnRequest=False`, reason `TooManyPorts`) |
| <Ref id="flag-doorman-ports-per-namespace">{'--doorman-ports-per-namespace'}</Ref> | `256` | Most doorman ports per namespace, its workloads together |
| <Ref id="flag-doorman-namespace">{'--doorman-namespace'}</Ref> | `$POD_NAMESPACE`, else `napwake-system` | The doorman Service's namespace |
| <Ref id="flag-doorman-health-check-user-agents">{'--doorman-health-check-user-agents'}</Ref> | | Comma-separated `User-Agent` prefixes of health checkers and scrapers, besides the built-in ones, whose `GET` and `HEAD` don't wake a workload. Helm value `doorman.healthCheckUserAgents` |
| <Ref id="flag-wake-key-secret">{'--wake-key-secret'}</Ref> | | The doorman's. A Secret in its namespace holding the key it signs the [Wake it button](/concepts/wake-on-request/#the-wake-it-button) with, which it fills when empty. Every replica must share it, since a click can reach any of them. Without it, each signs with its own, which works only for one replica. The chart sets `<fullname>-doorman-wake-key` |

### GKE forwarder

| Flag | Default | Description |
|------|---------|-------------|
| <Ref id="flag-neg-forwarder">{'--neg-forwarder'}</Ref> | `false` | Route Services behind GKE NEGs through a forwarder Deployment the operator runs in each paused workload's namespace, instead of leaving them unrouted. Needs `create` and `delete` on Deployments. Helm value `doorman.negForwarder.enabled`. See [GKE container-native load balancing](/concepts/wake-on-request/#gke-container-native-load-balancing-negs) |
| <Ref id="flag-neg-forwarder-image">{'--neg-forwarder-image'}</Ref> | | The forwarders' image, the operator's own. Required with `--neg-forwarder` |
| <Ref id="flag-neg-forwarder-replicas">{'--neg-forwarder-replicas'}</Ref> | `2` | Pods per forwarder. At least 1 |
| <Ref id="flag-neg-forwarder-resources">{'--neg-forwarder-resources'}</Ref> | `{"requests":{"cpu":"10m","memory":"32Mi"},"limits":{"memory":"64Mi"}}` | Each forwarder pod's resources, as JSON |
| <Ref id="flag-neg-forwarder-doorman-service">{'--neg-forwarder-doorman-service'}</Ref> | `napwake-doorman-pods` | Headless Service in `--doorman-namespace` selecting the doorman's pods, whose DNS name forwarders resolve |

### Modes

| Flag | Default | Description |
|------|---------|-------------|
| <Ref id="flag-doorman">{'--doorman'}</Ref> | `false` | Run as the doorman instead of the operator. The doorman Deployment sets it |
| <Ref id="flag-forwarder">{'--forwarder'}</Ref> | `false` | Run as a [forwarder](/concepts/wake-on-request/#gke-container-native-load-balancing-negs) instead of the operator. The operator's forwarder Deployments set it, with `--forward` (routes, comma-separated `listen=doorman` port pairs) and `--forwarder-doorman` (the doorman pods' DNS name) |
| <Ref id="flag-guard">{'--guard'}</Ref> | | Run as the chart's `uninstall` or `upgrade` hook (`guard.uninstall`, `guard.upgrade`). Waits up to two and a half minutes for ManagedWorkloads being deleted, then exits 1, listing those left without an operator. `uninstall` counts every one in `--watch-namespaces` (all when empty) or with the `napwake.dev/cleanup` finalizer. `upgrade` counts those with the finalizer outside the new `--watch-namespaces` |

### Checked at startup

The operator exits with an error naming the flag.

| Flag | Refused when |
|------|--------------|
| `--protected-namespaces` | A pattern isn't a valid glob |
| `--prometheus-url` | Not `http` or `https` with a host |
| `--prometheus-selector` | Not label matchers, or set without `--prometheus-url` |
| `--default-idle-after` | Under `1m` |
| `--default-cpu-threshold` | Outside 0.1 to 100, or more than two decimal places |
| `--default-forecast` | Not `eager`, `balanced` or `cautious` |
| `--default-wake` | Not `request` or `ask` |
| `--max-concurrent-reconciles`, `--doorman-ports-per-workload`, `--doorman-ports-per-namespace` | Below 1 |
| `--timezone` | Not a known IANA zone |

## Endpoints

| Endpoint | Port | Answers |
|----------|------|---------|
| <Ref id="endpoint-healthz">/healthz</Ref> | 8081 | Liveness. 200 while the process runs |
| <Ref id="endpoint-readyz">/readyz</Ref> | 8081 | Readiness. For the doorman, 200 once its routes are loaded and it reached the API server in the last 30 seconds. Fails while it can't listen on a routed port for over 30 seconds, and while shutting down |
| `/readyz`, a forwarder's | 8081, or the next port the workload doesn't serve, for both its probes | 200 while it reaches the doorman on every port it passes connections to. Fails once it starts shutting down |
| <Ref id="endpoint-metrics">/metrics</Ref> | 8443 in the chart | Prometheus metrics, HTTPS by default. See [Metrics](/reference/metrics/) |

## Leader election

```
--leader-elect=true
```

For HA, with more than one replica. The leader holds the Lease `479a98fc.napwake.dev` in the operator's namespace. A standby takes over if it fails.

## TLS configuration

```
--metrics-secure=false --metrics-bind-address=:8080
```

Plain HTTP. Not for production.

```
--metrics-cert-path=/certs/metrics
```

Your own certificate, not a self-signed one.

## Logging

| Flag | Default | Description |
|------|---------|-------------|
| <Ref id="flag-zap-log-level">{'--zap-log-level'}</Ref> | `info` | `debug`, `info`, `error`, `panic`, or a whole number above 0 for more verbose debug levels |
| <Ref id="flag-zap-encoder">{'--zap-encoder'}</Ref> | `json` | `json`, or `console` for logs to read by eye (`--zap-encoder=console`, the chart's `logEncoder: console`). The operator and the doorman log through `logr` (controller-runtime) |
| <Ref id="flag-zap-devel">{'--zap-devel'}</Ref> | `false` | Development defaults, with console encoding, debug level and stack traces from warnings |
| <Ref id="flag-zap-stacktrace-level">{'--zap-stacktrace-level'}</Ref> | `error` | The level stack traces start at, `info`, `error` or `panic` |
| <Ref id="flag-zap-time-encoding">{'--zap-time-encoding'}</Ref> | RFC 3339 | `epoch`, `millis`, `nano`, `iso8601`, `rfc3339` or `rfc3339nano` |

The key fields in log entries.

| Field | What it holds |
|-------|---------------|
| `name`, `namespace` | The object reconciled, such as the ManagedWorkload. controller-runtime adds them to all its entries, with `controller` and `reconcileID` |
| `workload` | The workload or ManagedWorkload an entry names itself, with its `namespace` |
| `from`, `to` | Phases of a `phase transition` entry |
| `reason` | What caused a phase transition |
| `phase` | Phase after a reconcile, on `reconciled` entries at debug level (`--zap-log-level=debug`) |
| `error` | What went wrong, on failure entries |
