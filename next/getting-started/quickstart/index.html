Getting started

Quickstart

Take one workload from idle and costing money to paused while idle and woken when used. You measure it first, so nothing pauses until you say so.

Before you start

You need Napwake installed, the kubectl plugin and metrics-server. Napwake reads CPU from it, and won’t pause a workload whose CPU it can’t read.

If the Metrics API is missing or not Available, install metrics-server:

Cluster metrics-server
GKE, AKS Runs by default
minikube Off when new. minikube addons enable metrics-server
EKS Off. The metrics-server add-on, or the manifest
kind Off. The manifest, then the patch
Others The manifest

On kind, kubelet certificates aren’t signed for their addresses. The patch tells metrics-server not to verify them. Local test clusters only.

kubectl top pods -A shows numbers within a minute or so once it works. If a workload still won’t pause, see Troubleshooting.

The scan shows whether each workload is idle and why, and what it costs while it runs. Leave out -n to scan every namespace.

In a terminal on your desktop, it also opens the report in your browser. --open=false keeps it in the terminal.

Section titled “3. Opt it in, measuring first”

The annotations are its settings, set first so it starts in dry-run, measured and never paused. The label opts it in.

idle-after=5m keeps the example quick. The default is an hour.

In real use, they go in the manifest or Helm values, or on the namespace for everything in it. See Opting in, Kustomize included.

4. Watch it measure

Section titled “4. Watch it measure”

For my-api, STATE reads running (dry-run), and NEXT says when it would pause. LAST ACTIVITY says when it was last active and from what. Until there’s been any, it reads none since Napwake began managing it.

After idle-after with no activity, STATE reads idle (dry-run) and an event says it would have paused. Nothing is scaled down. Mark it active, as a developer portal or your tooling would, to end the would-be pause:

status now leads with what dry-run measured. WOULD FREE is what the would-be pauses would have freed.

With a workload of your own

Measure it a few days, across a weekend if it’s used on weekdays, before going live. See Dry run.

Requests to a running workload count only through a Prometheus query. So an nginx serving the odd request on almost no CPU would pause. If yours won’t turn idle, LAST ACTIVITY and NEXT say why.

CheckpointAwake · dry-run

WOULD FREE reads <$0.01, and <$1 in status. A few minutes of a sample this small free less than a cent.

5. Let it pause

Section titled “5. Let it pause”

If Argo CD or Flux applies it

Skip this for the sample. A tool that applies replicas from Git undoes every pause. Napwake then waits an hour to pause again (GitOpsConflict).

Before you enable, have it leave replicas to Napwake, as in GitOps tools. The scan’s notes list affected workloads. Those with an HPA are already set.

It sets napwake.dev/dry-run to "false". After idle-after with no activity, which NEXT counts down, Napwake scales my-api to zero and remembers its 2 replicas.

6. Wake it with a request

Section titled “6. Wake it with a request”

Wait 5 minutes after READY reads 0/0. A request or a wake sooner makes it a wrong pause. Napwake would then warn PausedWhileInUse, and wait 10 minutes before pausing again.

The doorman holds the request and wakes my-api. A browser coming through an Ingress or a Gateway gets a waking-up page, which loads the app once it’s up.

kubectl port-forward goes straight to a pod, so it can’t reach a paused workload. Wake it first:
